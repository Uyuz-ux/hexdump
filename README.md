# hexdump

Classic hex dump formatting and parsing for Nim, following `xxd`'s
default layout: address column, grouped lowercase hex bytes, and an
ASCII gutter. Anything the module can dump, `parseDump` can read back -
the round trip is byte-exact.

```nim
import hexdump

echo dump("Hello, world!")
## 00000000: 4865 6c6c 6f2c 2077 6f72 6c64 21         Hello, world!

let back = parseDump(dumpLines("Hello, world!"))
assert back == "Hello, world!"
```


## Usage

```nim
import hexdump

let data = "Hello, world!"

# One string, ready to print (each line ends with a newline):
echo dump(data)

# Line by line, for example when streaming output:
for line in dumpLines(data):
  echo line

# Custom layout: 8 bytes per line, one space between bytes:
let opts = DumpOptions(width: 8, group: 1, baseAddr: 0, unprintable: '.')
echo dump(data, opts)
# 00000000: 48 65 6c 6c 6f 2c 20 77  Hello, w
# 00000008: 6f 72 6c 64 21           orld!

# Decode a dump back into bytes (ignores address and gutter columns):
let original = parseDump(dumpLines(data))
assert original == data
```

## API

| Signature | What it does |
|---|---|
| `dumpLines(data, opts = defaultDumpOptions()): seq[string]` | One hex dump line per entry, no trailing newlines. |
| `dump(data, opts = defaultDumpOptions()): string` | `dumpLines` joined with newlines plus a trailing newline. |
| `parseDump(lines: openArray[string]): string` | Decodes dump lines back to bytes; never raises. |
| `parseDump(dump: string): string` | Same, taking the whole dump text. |
| `defaultDumpOptions(): DumpOptions` | xxd defaults: 16 bytes/line, pairs per group, `.` placeholder. |
| `validateOptions(opts)` | Raises `ValueError` on impossible layouts. |

`DumpOptions` fields: `width` (bytes per line), `group` (bytes per hex
group), `baseAddr` (address of the first byte), `unprintable`
(placeholder character).

## Semantics and guarantees

- **Byte-exact round trip.** `parseDump(dumpLines(x)) == x` holds for
  any bytes and any layout the module accepts; the suite checks this
  over a 2000-byte random corpus, every length from 1 to 40, and
  several custom layouts.
- **xxd-compatible layout.** The default rendering matches xxd's
  defaults: 16 bytes per line, bytes grouped in pairs, lowercase hex,
  an 8-hex-digit address column, and `.` for bytes outside the
  printable range 0x20..0x7e (space through tilde).
- **Golden-reference tested.** The suite pins the rendering against
  lines generated by an independent Python reference implementation,
  so the two implementations had to agree byte for byte.
- **Addresses truncate like xxd.** Addresses wider than 32 bits are
  cut to the low 32 bits, matching xxd's `%08x` formatting.
- **Parsing never raises.** Blank lines and lines without an address
  column are skipped, so truncated or mixed input degrades to "parse
  what you can" instead of losing the whole dump.
- **UTF-8 friendly.** Matching is byte-oriented; because UTF-8 is
  self-synchronizing, byte-level offsets never start mid-code-point.
  The gutter shows one placeholder per *byte*, exactly like xxd - the
  lossless view you need to inspect encoding problems.
